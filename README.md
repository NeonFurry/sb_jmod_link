# SB <-> JMod Link

**Версия: 7.3**

Аддон для Garry's Mod, который связывает энергосистемы **Spacebuild (SB)**, **JMod** и **CAF (Resource Distribution / Life Support)** в единую сеть. Перекачивает энергию между банками JMod, генераторами SB и хранилищами CAF (`storage_energy` и любыми другими устройствами, зарегистрированными в RD-сети).

> ⚡ Простой пример: банк JMod питает генератор SB, а хранилище CAF заряжается от реактора — всё через один тул.

---

## Возможности

- **Двусторонняя перекачка энергии** — Spacebuild (`energy`) ↔ JMod (`Electricity`) ↔ CAF/RD.
- **Умное распознавание устройств** — через `RD.GetEntityTable`: любые девайсы Life Support цепляются без списков исключений.
- **Тул «SB <-> JMod Link»** — соединение устройств в пару кликов.
- **Динамический трос** — физический трос между устройствами **бесконечно растягивается**, если оттащить устройство далеко, и **сам стягивается**, когда приборы снова сближаются. Альтернатива — визуальный лазерный луч.
- **EZ-батарея как расходник (контактная зарядка)** — приложите заряженную `ent_jack_gmod_ezbattery` к устройству, и заряд начнёт **сам перетекать при касании** порциями. Пустая батарея исчезает с искрами. Работает с водяными насосами, верстаками, турелями, банками — со всеми структурами, которые распознаёт мод.
- **Удаление связей по клавише R** — наведи на устройство со связями и нажми R: уберутся все его соединения вместе с тросом.
- **Гибкая скорость перекачки** — от 1 до 100 000 ед/сек, задаётся в меню тула.
- **Умная горячая перезагрузка** — команда `sbjmod_reload` сама сканирует папки аддона, подхватывает **изменённые и новые** файлы и синхронизирует клиентскую часть у всех игроков. Карта перезагружать не нужно.

## Установка

1. Скопируйте папку `sb_jmod_link` в `garrysmod/addons/`.
2. Убедитесь, что установлены и включены аддоны-поставщики ресурсов:
   - **Spacebuild / CAF** (Resource Distribution, Life Support);
   - **JMod**.
3. Перезапустите GMod **или** перезагрузите карту (один раз — после установки).
4. Включите RD **до** спавна накопителей — иначе устройства не попадут в реестр RD и не будут распознаны.

Структура аддона:

```
sb_jmod_link/
    lua/
        autorun/
            sb_jmod_link.lua                  — ядро: тул, идентификация устройств, связи, команды
            sb_jmod_hotreload.lua             — умная перезагрузка: сканирует папки, подхватывает новые файлы
            server/
                sb_jmod_ezbattery.lua         — серверная логика: контактная зарядка EZ-батареями
        sb_jmod/
            transfer.lua                      — насос (перекачка ресурсов)
            rope.lua                          — динамический физический трос
            caf.lua                           — мост RD/CAF
            autolink.lua                      — патч Auto Link Tool (rd3_dev_link)
```

## Использование

### Тул «SB <-> JMod Link»

Находится в категории **Construction**.

| Действие | Результат |
|---|---|
| **ЛКМ** по устройству | Выбрать первое устройство; второй ЛКМ — создать связь |
| **ПКМ** по первому устройству | Задать цель 1; следующая ПКМ — цель 2; ещё одна ПКМ — создать связь |
| **R** по устройству со связями | Убрать **все** связи этого устройства (вместе с тросом) |
| **R** по устройству без связей / в пустоту | Сбросить выбор |

В меню тула настраиваются:
- **Скорость перекачки** (ед/сек);
- **Физический трос** (вкл/выкл — иначе между устройствами рисуется лазерный луч);
- **Провис троса**.

### Динамический трос

Трос ведёт себя как настоящий кабель на катушке:

- оттащили устройство физганом хоть через всю карту — трос бесконечно удлиняется;
- принесли обратно — трос сам укоротился и снова слегка провис;
- обновление длины происходит каждые 0,2 секунды через `SetKeyValue("addlength", ...)`, без пересоздания констрейнта.

### Контактная зарядка EZ-батареей

1. Возьмите заряженную `ent_jack_gmod_ezbattery` (в руках или физганом).
2. **Приложите её к устройству** — банку JMod, водяному насосу, `storage_energy` из Life Support — на расстояние касания (50 ед. по умолчанию).
3. Заряд начнёт **сам перетекать порциями** (25 ед/сек по умолчанию). Коснулись на секунду — перешла «частичка», держите рядом — перельётся больше.
4. Когда батарея опустеет — она **исчезнет с искрами и звуком разряда**.
5. Если ёмкость приёмника заполнена — контактирование ничего не делает, батарея ждёт.

**Разовый дамп по E** сохранён как дополнение: наведитесь на батарею и нажмите E — заряд перельётся целиком одним махом, без ожидания. Если рядом нет совместимого устройства, E работает как обычный подбор батареи в инвентарь JMod.

Настройки:

| Команда | По умолчанию | Описание |
|---|---|---|
| `sbjmod_ezbat_touch 1/0` | 1 | Вкл/выкл контактный перелив |
| `sbjmod_ezbat_touchdist` | 50 | Дистанция «касания» |
| `sbjmod_ezbat_rate` | 25 | Скорость перелива, ед/сек |
| `sbjmod_ezbat_range` | 150 | Радиус поиска устройства для разового дампа по E |

### Горячая перезагрузка

Команда `sbjmod_reload` (для админов) делает всё сама:

- сканирует аддон через `file.Find` — ядро, все `lua/autorun/server/sb_jmod_*.lua` и всё содержимое `lua/sb_jmod/*.lua`;
- подхватывает **изменённые и добавленные** файлы — жёсткого списка нет;
- сохраняет состояние: активные связи, тросы и настройки не сбрасываются;
- по сети (`SBJMOD_ReloadCL`) автоматически перезагружает клиентскую часть у всех игроков — вручную `sbjmod_reload_cl` набирать не нужно (хотя старая команда осталась рабочей);
- выводит отчёт: каждый файл со статусом OK/ошибка и итоговое число перезагруженных файлов.

> ⚠️ Единственное ограничение движка: **удалённый** файл нельзя выгрузить без смены карты — его хуки и таймеры останутся активными до перезапуска. Изменение и добавление файлов отрабатывают без перезагрузки карты.

Типичный цикл разработки: отредактировал файл → сохранил → `sbjmod_reload` → взял тул заново → проверяешь.

### Консольные команды

| Команда | Описание |
|---|---|
| `sb_jmod_dump` | Список всех связей: классы устройств, типы, скорость, ресурс (для админов) |
| `sbjmod_select` | Выбрать устройство под прицелом |
| `sbjmod_link` | Связать выбранное устройство с устройством под прицелом |
| `sbjmod_reset` | Сбросить выбор |
| `sbjmod_reload` | Умная перезагрузка всех модулей аддона (для админов) |
| `sbjmod_reload_cl` | Ручная перезагрузка клиентской части (обычно не нужна) |
| `sbjmod_ezbat_touch` | Вкл/выкл контактный перелив от батареи |
| `sbjmod_ezbat_touchdist` | Дистанция касания для контактного перелива |
| `sbjmod_ezbat_rate` | Скорость перелива от батареи |
| `sbjmod_ezbat_range` | Радиус поиска для разового дампа по E |

## Как это работает

Ядро аддона — функция `SB_JMOD.Identify`, которая определяет тип устройства:

1. **JMod** — энтити имеет методы `GetElectricity` / `SetElectricity`; ёмкость читается из поля `MaxElectricity`;
2. **SB** — энтити имеет методы `GetResourceAmount` / `SetResourceAmount`;
3. **CAF (RD)** — устройство зарегистрировано в RD-сети через `RD.GetEntityTable` (покрывает `storage_energy`, генераторы и любые другие девайсы Life Support);
4. Запасной вариант по префиксам классов (`storage_`, `generator_`, `other_`, `residue_`), если RD ещё не успел зарегистрировать свежезаспавненный девайс.

Связи синхронизируются с клиентом по сети (`SBJMOD_Links`, каждые 5 секунд) — для отрисовки лучей. Перекачка, динамический трос и контактная зарядка работают на серверных таймерах. Вся работа с зарядом обёрнута в `pcall` — отсутствие какого-либо API у конкретного устройства не уронит сервер.

Бонус совместимости: батарею можно положить рядом с устройством, соединённым динамическим тросом, — она будет подпитывать банку, а банка через трос — всю сеть.

## Совместимость

- ✅ Spacebuild (энергосистема `energy`)
- ✅ JMod (ресурс `Electricity` — водяные насосы, верстаки, турели и другие EZ-машины)
- ✅ CAF / Resource Distribution — через реестр RD
- ✅ Auto Link Tool (`rd3_dev_link`) — подключает банки JMod к нодам RD-сети после патча из модуля `autolink`
- ✅ EZ-Battery (`ent_jack_gmod_ezbattery`) — как расходный носитель заряда (контактный перелив + разовый дамп)

## Устранение неполадок

| Проблема | Решение |
|---|---|
| Тул пишет «Это не устройство SB/JMod/CAF» | Убедитесь, что RD включён **до** спавна устройства; пересоздайте устройство |
| В `sb_jmod_dump` у устройства стоит `?` | Адаптер не подошёл под класс — сообщите класс (из спавн-меню) |
| Связь создана, но энергия не идёт | Проверьте, что в `transfer.lua` есть ветка для типа `caf` через `RD.GetResourceAmount` / `RD.SetResourceAmount` |
| Тул не появился в меню | Полный перезапуск игры — тул регистрируется загрузчиком |
| Трос не стягивается обратно | Наберите `sbjmod_reload` — модуль троса перезагрузится |
| Контактный перелив не срабатывает | Хранилище полное или батарея пуста; проверьте `sbjmod_ezbat_touch 1` и дистанцию `sbjmod_ezbat_touchdist` |
| Новый файл не подхватился | Наберите `sbjmod_reload`; если файл был удалён — поможет только смена карты (ограничение движка) |
