## Что это

Аддон связывает устройства разных модов **логической «невидимой» связью**: ресурс перетекает мгновенно, кабели и лучи не нужны. Связь создаётся тулом, живёт на сервере и не привязана к физике — устройства можно двигать.

- Ресурс связи: `energy`, `water`, `oxygen`, `nitrogen`, `hydrogen`, `carbon dioxide`, `steam`, `heavy water`, `liquid nitrogen` — выбирается автоматически или вручную.
- JMod-энергия: машины (`GetElectricity`) и батареи (`power`).
- JMod Legacy: турели, тесла, терминал и предмет-батарея — по полю `BatteryCharge`.
- Fusion Generator: лимиты воды и энергии, бесконечная вода, отключение урона.

| Мод | Ресурс | Устройства |
|---|---|---|
| **JMod** | `Electricity` / `power` | Генераторы, power bank, турели, батареи |
| **SpaceBuild 3 / CAF** | все ресурсы RD3 | `storage_*`, `resource_node`, генераторы, `base_air_exchanger` |
| **JMod Legacy** | `BatteryCharge` | `ent_jack_turret_*`, `ent_jack_teslasentry`, `ent_jack_terminal`, `ent_jack_aidcomm`, `ent_jack_turretbattery` |

## Установка

1. Скачайте последнюю версию из раздела [Releases](../../releases).
2. Распакуйте в `garrysmod/addons/sb_jmod_link/`.
3. Перезапустите сервер или переподключитесь.

**Требования**

- Garry's Mod (любая актуальная ветка).
- *Опционально:* SpaceBuild 3 с CAF / Resource Distribution — для SB-устройств.
- *Опционально:* JMod или JMod Legacy — для JMod-устройств.

## Быстрый старт

Откройте Spawn Menu (`Q`) → вкладка **SBJLink** → **Take Tool**, либо выберите инструмент во вкладке Tool.

| Клавиша | Действие |
|---|---|
| **ЛКМ** | Выбрать устройство → второй клик по партнёру создаёт связь |
| **ПКМ** | Пошаговый режим: цель 1 → цель 2 → связь |
| **R** | Убрать все связи выбранного устройства |

**Выбор ресурса.** В панели тула есть список ресурсов. Он запоминается в `sb_jmodlink_res` и отправляет на сервер `sbjmod_res <ресурс>`; без выбора действует автоопределение по общим ресурсам пары. Ресурс фиксируется в момент создания связи.

> [!TIP]
> Для воды и газов удобно связать `storage_...` с потребителем: накопитель отдаёт, `base_air_exchanger` и подобные только принимают.

## Fusion Generator

Отдельный модуль для `generator_energy_fusion` (SpaceBuild / Life Support). Настройки — во вкладке **SBJLink** или конварами.

| Возможность | Что делает |
|---|---|
| 🛡️ Без повреждений | Блокирует урон от перегрева и нехватки воды (по умолчанию **выключено**) |
| 💧 Лимит воды | Меняет ёмкость бака конкретного генератора |
| ⚡ Лимит энергии | Ограничивает запас **всей RD-сети** (см. предупреждение ниже) |
| ♾️ Бесконечная вода | Генератор не расходует воду и не «сгорает» |

### Лимит энергии и RD-сеть

> [!WARNING]
> В RD3 `energy` хранится одним значением на всю сеть (`nettable[netid].resources.energy.value`). Лимит энергии — это потолок **сетевого** запаса, поэтому он режет и банки `storage_energy`, и другие генераторы этой сети.

> [!NOTE]
> Лимит воды такого эффекта не имеет: он меняет ёмкость бака прибора, а сетевое значение не трогает.

**Рекомендация:** держите Fusion в отдельной RD-сети (Link Tool → `Create new network`) — тогда кламп затрагивает только его выработку.

## Совместимость

| Мод | Статус | Примечание |
|---|---|---|
| JMod | ✅ | Машины — `GetElectricity`, батареи — `Resource`/`power` |
| JMod Legacy (Workshop `2157935882`) | ✅ | Поле `BatteryCharge`; генератор и `powernode` не конвертируются |
| SpaceBuild 3 / CAF | ✅ | Все ресурсы RD3 через `RD.*` |
| Auto Link Tool | ✅ | Клик по ноде подключает JMod-устройства в радиусе |
| Fusion Generator | ✅ | Лимиты, вода, урон |
| Прочие моды на RD3 | ⚠️ | Работают через `caf.lua`, если используют стандартный API |
| Моды со своим ресурсным движком | ❌ | Без RD3/CAF не подключаются |

Факты по API сверены с исходниками: [spacebuild/spacebuild](https://github.com/spacebuild/spacebuild), [Jackarunda/gmod](https://github.com/Jackarunda/gmod); JMod Legacy разбирался по распакованному `addon.gma`.

## Архитектура

```text
lua/
├── autorun/
│   ├── sb_jmod_link.lua           ядро: тул, реестр типов, связи, HUD
│   ├── sb_jmod_hotreload.lua      горячая перезагрузка (sbjmod_reload)
│   ├── client/
│   │   └── sb_jmod_tab.lua        вкладка SBJLink в Spawn Menu
│   └── server/
│       └── sb_jmod_ezbattery.lua  перелив заряда из EZ-батарей
├── sb_jmod/
│   ├── transfer.lua               насос ресурсов и роли устройств
│   ├── caf.lua                    мост к CAF / Resource Distribution
│   ├── autolink.lua               совместимость с Auto Link Tool
│   ├── jmodlegacy.lua             JMod Legacy (ent_jack_)
│   ├── fusion.lua                 патч Fusion Generators
│   └── rope.lua                   заглушка: физический трос отключён
└── weapons/gmod_tool/stools/sb_jmodlink.lua
```

| Модуль | Роль |
|---|---|
| `transfer.lua` | Насос (0,1 с): правила `генератор → приёмник`, `банк ↔ банк 1:1`, потребитель только принимает; таблица ролей `SB_JMOD.DeviceRoles` |
| `caf.lua` | Доступ к RD: `GetEntityTable`, `GetResourceAmount`, `Supply/Consume` |
| `autolink.lua` | Патч Auto Link Tool: нода подключает JMod-устройства в радиусе |
| `jmodlegacy.lua` | Распознавание `ent_jack_*` по полю `BatteryCharge` и флаги включения |
| `fusion.lua` | Персональные переопределения методов генератора, кламп сети |
| `rope.lua` | Пустые обработчики для совместимости с ядром |

<details>
<summary><b>Как это работает с RD3</b></summary>

- `RD.GetEntityTable` / `RD.GetNetTable` — чтение таблиц RD; `ent_table[entid].network` даёт сеть прибора.
- `GetResourceAmount(ent, res, sumconnectednets)` — третий аргумент по умолчанию **true** и суммирует соседние сети, поэтому мод передаёт `false` и работает в пределах своей сети.
- `RD.AddResource` не используется для смены ёмкости: он присваивает `value` и обнуляет содержимое.
- Запас меняется дельтой через `SupplyResource` / `ConsumeResource`.
- Если оба конца связи в одной сети, перекачка пропускается: ресурс у них общий, а дельта-запись иначе дала бы двойное начисление.

</details>

## Известные ограничения

- **Лимит энергии глобальный по RD-сети.** Для точной настройки — отдельная сеть на Fusion.
- **Связи живут в памяти сервера.** Не сохраняются в сейв и не поддерживаются Duplicator/AdvDupe2.
- **Перекачка мгновенная.** Отдельной скорости или КПД нет: наполнение до ёмкости в пределах тика (0,1 с).
- **Отходы не поддержаны.** В RD3 нет `air`/`food`/`waste`; воздух — это `oxygen`. Для `waste` нужно обратное направление ролей.
- **Ресурс фиксируется при создании связи.** Сменить — только снять и создать заново.
- **HUD передаёт до 4096 связей**; лишние не попадут в пакет.
- **JMod Legacy:** топливо `ent_jack_generator` (`Remaining`) и хаб `ent_jack_powernode` не преобразуются; без `sbjmod_legacy_power_flags` турелям нужна физическая вставка батарей.
- Патчи Fusion проверены на актуальной ветке SpaceBuild; на других версиях `resourcedistribution.lua` поведение может отличаться — проверяйте `sbjmod_fusion_scan`.

## Журнал изменений

<details>
<summary><b>9.6 — панель тула</b></summary>

- Панель инструмента в стиле вкладки SBJLink: карточки, живой счётчик связей, выбор ресурса, тумблеры HUD, кнопки диагностики и сброса.

</details>

<details>
<summary><b>9.4 – 9.5 — JMod Legacy</b></summary>

- Совместимость проверена по распакованному `addon.gma` (400 Lua-файлов).
- Энергия legacy — поле `BatteryCharge`, ёмкость `MaxCharge` / `BatteryMaxCharge`.
- Запись поля напрямую с клампом, оживление «мёртвой» батареи (`Dead = false`).
- Legacy-устройства с зарядом считаются приёмниками.
- EZ-батарея понимает `ent_jack_turretbattery`.
- `sbjmod_legacy_power_flags` поднимает флаги `HasBattery` / `HasBatteryOne+Two`.

</details>

<details>
<summary><b>9.1 – 9.2 — мультиресурсные связи</b></summary>

- Связи несут любой ресурс RD3; роли по реальным классам SB (`generator_recycler_*`, `generator_gas_*`, `base_air_exchanger`).
- JMod-батареи распознаются как источник (`GetResource` / `MaxResource`).
- EZ-батарея переписана на `TryLoadResource` и дельту RD.
- HUD ресурсов прибора.

</details>

<details>
<summary><b>9.0 — безопасность и стабильность</b></summary>

- Реестр определителей `SB_JMOD.AddIdentifier` вместо цепочки обёрток.
- Права на связи (`sbjmod_open_links`), настройки Fusion только для админа.
- Синхронизация связей по изменению, счётчик 16 бит.
- `OnEntityCreated` вместо несуществующего `EntitySpawned`, постоянный скан генераторов.
- Заводские ёмкости запоминаются при `AddResource`; лимит воды не подрезает расход.

</details>
